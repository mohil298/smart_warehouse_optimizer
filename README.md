# Smart Warehouse Management & Delivery Optimization System

M.Tech DSA project built with Python 3.11, Streamlit and SQLite.

## Features
- Inventory: add, search, update stock and delete products
- Interactive warehouse layout: browse aisle/shelf cards, inspect shelf contents and update stock from the layout
- Orders: place orders, reserve stock and update order status
- Priority scheduling: urgent orders are shown first using a heap-based priority queue
- Delivery routing: step-by-step Dijkstra visualizer with a weighted network diagram, current edge, visited nodes, tentative distances, and final shortest route
- DSA demonstration: priority heap, greedy shelf picking and First-Fit Decreasing vehicle allocation
- Dashboard: stock, pending orders, completed orders and low-stock count

## Setup (Windows 10/11, VS Code)
1. Install Python 3.11 and VS Code.
2. Extract the ZIP to a simple folder such as `C:\MTech\smart_warehouse_delivery_system`.
3. Open VS Code -> File -> Open Folder -> select the extracted folder.
4. Open Terminal -> New Terminal.
5. Create a virtual environment:
   `py -3.11 -m venv .venv`
6. Install packages without activating the environment:
   `.\.venv\Scripts\python.exe -m pip install --upgrade pip`
   `.\.venv\Scripts\python.exe -m pip install -r requirements.txt`
7. Start the application:
   `.\.venv\Scripts\python.exe -m streamlit run app.py`
8. Streamlit opens a browser tab. If it does not, visit `http://localhost:8501`.

Using the environment's Python executable directly avoids the PowerShell activation-policy issue.

## First run
A local `warehouse.db` SQLite database is created automatically. Six sample products are inserted the first time. Do not delete `warehouse.db` unless you want to reset all project data; to reset, stop Streamlit, delete the database file and run again.

## Dijkstra visualizer
Open **Delivery Optimizer**, choose a customer zone, and use **Next**, **Previous**, **Reset**, or the **Animation step** slider. The network highlights the node currently being processed, visited locations, the edge being checked, and (at the final step) the shortest route. Distance labels on nodes are the current tentative distances maintained by Dijkstra's algorithm.

The visualizer is step-driven rather than time-driven, so you can pause at each event and explain it during a project demonstration or viva. It uses SVG generated by the app and requires no extra package.

## DSA complexity
- Dijkstra with adjacency list + binary min-heap: O((V + E) log V)
- Heap push/pop for priority queue: O(log n)
- Sorting products for shelf picking: O(n log n)
- Dictionary average lookup: O(1)
- First-Fit Decreasing: O(n log n + n*k), where k is number of vehicles in this implementation.

## Important notes
- Distances and delivery locations are illustrative sample data, not live maps or GPS.
- This is an academic prototype. It does not connect to real courier services or live vehicle tracking.
- The project deliberately avoids Pandas and uses only Streamlit plus Python's standard library to reduce Windows DLL compatibility issues.

## Troubleshooting
### `streamlit` is not recognized
Run it through the virtual environment:
`.\.venv\Scripts\python.exe -m streamlit run app.py`

### PowerShell says scripts are disabled
Do not activate the environment. Use the `.venv\Scripts\python.exe` commands above.

### DLL / Application Control error
This project does not require Pandas, NumPy, or NetworkX. If a package DLL is blocked by your Windows policy, share the exact error with your system administrator. Install only the Streamlit dependency listed in `requirements.txt`.

## Smart Delivery Assignment
Open **Smart Delivery Assignment**, choose the available vehicle count and capacity, then generate a plan. The scheduler prioritizes urgent orders, then larger orders, and uses a First-Fit capacity heuristic to allocate orders to vehicles. Dijkstra calculates a warehouse-to-destination route estimate for each assigned order. Vehicle, route estimate and assignment timestamp are saved in SQLite and shown in the Orders and Analytics pages. Delivered orders are not cleared when active assignments are reset.

**Capacity assumption:** until package weight/dimensions are added to the inventory schema, one unit means one ordered product unit. It is not kilograms. The route network is illustrative and does not include live traffic or multi-stop sequencing.

## Advanced Analytics and modern interface
The **Advanced Analytics** workspace includes order status and priority charts, daily order creation trend, category stock chart, low-stock/reorder table, destination demand and vehicle workload/dispatch coverage. Aggregates are queried directly from SQLite, so Pandas and NumPy are not required. The app now uses a responsive wide layout, a dark navigation sidebar, dashboard-style metric cards, tabs and cleaner data tables.

The database performs an additive migration for vehicle assignment fields when the app starts. Existing `warehouse.db` inventory and order records are preserved.
